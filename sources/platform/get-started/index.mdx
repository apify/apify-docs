Apify is a cloud platform for web scraping, data extraction, and automation. Everything on it revolves around _Actors_ - serverless programs that run in the cloud. You can run Actors that other people built, build your own, and connect either one to the rest of your stack. This page explains how the platform fits together and where to start.

## How Apify works

An Actor takes a structured JSON input, performs a job - scraping a website, automating a browser, processing data - and stores its results on the platform. Results typically land in a structured dataset you can export or send elsewhere. You can start an Actor manually in Apify Console, call it through the [API](/api/v2), or put it on a [schedule](/actors/running/schedules).

Because every Actor shares this input > run > output model, they compose. One Actor's output can feed another, results flow into [integrations](/integrations) like Make, Zapier, or n8n, and you can call any Actor from your code like a regular API.

For how the platform is built, what happens during a run, and how workloads stay isolated, see [Platform architecture](/security/architecture).

## How Actors get to Apify Store

[Apify Store](https://apify.com/store) holds thousands of public Actors built by Apify and the community. Each one started as code that a developer wrote, deployed to the platform, and published - optionally setting a price, since Store Actors can [earn their developers money](/actors/publishing).

You can stand on either side of that exchange. Run other people's Actors to get data without writing code, or build your own - for yourself, your team, or as a product in Store.

## How the capabilities fit together

Actors are the unit of work. The rest of the platform exists to run them, hold what they produce, and connect them to everything else. Each section of these docs covers one part:

- [Actors](/actors) - run Actors from Store, build your own, publish and monetize them.
- [Storage](/storage) - datasets, key-value stores, and request queues. Every run writes its results here.
- [Proxy](/proxy) - datacenter and residential IP addresses so your Actors can access websites reliably.
- [Integrations](/integrations) - the API, webhooks, workflow platforms, and data destinations that connect Actors to your stack.
- [For AI agents](/agents) - the Apify MCP server, Agent Skills, and plugins that let agents and coding assistants use Actors.
- [Account](/account) - organizations, access rights, billing, and limits.
- [Security](/security) - how the platform protects your data and what it is certified for.

## SDKs, API, and CLI

Everything you can do in Apify Console you can also do from code. The [REST API](/api/v2) covers the whole platform, with official clients for [JavaScript](/api/client/js) and [Python](/api/client/python). To build Actors, use the [SDK for JavaScript](/sdk/js) or the [SDK for Python](/sdk/python), and the [CLI](/cli) to create, run, and deploy them from your terminal. Apify also maintains open-source libraries such as [Crawlee](https://crawlee.dev), which you can use with or without the platform.

## Pricing

Running Actors consumes platform usage, such as compute, storage, and proxy traffic. Some Store Actors charge per event instead, for example per result. Your plan sets your monthly usage, limits, and features. For the models, see [Actors in Store](/actors/running/actors-in-store) and [Usage and resources](/actors/running/usage-and-resources); for your account, see [Limits](/account/limits) and [plans](https://apify.com/pricing).

## Run your first Actor

The quickest way to understand the platform is to run something. Open [Apify Store](https://apify.com/store), pick an Actor, select **Start**, and watch the results arrive. No code required.
