Apify agent tools connect an AI agent to the Apify platform. The [MCP server](/mcp) is the live connection an agent uses to search [Apify Store](https://apify.com/store), run Actors, and read the results. [Agent Skills](/agent-tools/skills) carry the procedure for multi-step work, such as building and deploying an Actor. A [plugin](/agent-tools/plugin) installs both in one step for a specific coding agent.

Two more pieces round out the set. [Docs for agents](/agent-tools/docs-for-agents) lists the machine-readable surfaces an agent can read, and [agentic payments](/agent-tools/agentic-payments) let an agent pay for Actor runs without an Apify account. To run your first Actor from an agent, follow the [agent quickstart](/get-started/agent-onboarding).

## Key concepts

The pieces stack rather than compete, and most setups use more than one:

| Piece | What it is | Reach for it when |
| :--- | :--- | :--- |
| [MCP server](/mcp) | A hosted server at `mcp.apify.com` with tools to search Apify Store, run Actors, and search the Apify documentation, plus optional tools for runs, storage, tasks, and schedules. | Your agent needs to act on Apify: find an Actor, run it, and get structured data back. |
| [Plugin](/agent-tools/plugin) | One install for a specific coding agent. Most plugins bundle the MCP server, Agent Skills, and an `apify` routing agent. The OpenClaw, Hermes Agent, and Kilo Code plugins add native Apify tools instead of the MCP server. | Your coding agent has a plugin and you want the whole setup in one step. |
| [Agent Skills](/agent-tools/skills) | Instructions your agent loads when a task matches, such as building an Actor or choosing a scraper. | Your agent already connects to Apify and you want it to follow a tested multi-step workflow. |
| [Docs for agents](/agent-tools/docs-for-agents) | Every documentation page as Markdown, `llms.txt` indexes, and the agent-facing files on apify.com. | Your agent needs current Apify documentation instead of its training data. |
| [Agentic payments](/agent-tools/agentic-payments) | Pay-per-use access for agents without an Apify account, through the Apify Agent General Interface. | Your agent has to pay for Actor runs on its own. |

The MCP server gives an agent *capability*, and Agent Skills give it *procedure*. With the MCP server alone, an agent can call any tool but has to work out the sequence itself. With skills, it follows a workflow Apify has already tested.

## Build on Apify instead

The pages above cover agents that *call* Apify. These adjacent topics cover building on the platform:

- [Develop AI agents on Apify](/actors/development/quick-start/develop-ai-agents) - Build an agent that runs as an Actor on the Apify platform.
- [Build Actors with AI](/actors/development/quick-start/build-with-ai) - Use a coding agent to create and deploy an Actor.
- [MCP connectors](/integrations/mcp-connectors) - Let an Actor you built act on a user's third-party accounts, such as Notion, Slack, or GitHub.
- [AI integrations](/integrations/ai) - Call Apify from agent frameworks such as LangChain, CrewAI, and the Vercel AI SDK, and load results into vector databases.
- [API client libraries](/api/v2) - Call the Apify API from your own application code, or use the [JavaScript](https://docs.apify.com/api/client/js) and [Python](https://docs.apify.com/api/client/python) clients.
